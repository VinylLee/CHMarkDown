# CHMarkDown 开发路线图

## 1. 文档目的

本文档用于规划 CHMarkDown 后续版本的开发顺序。

执行规则：

- 严格按版本顺序开发
- 每次只实现一个版本
- 当前版本通过测试、构建和功能验收后，再进入下一个版本
- 路线图只定义目标和边界；开始某个版本前，再补充详细技术方案
- 不提前实现后续版本功能

## 2. 当前基线：v1.0.7

当前已完成的功能和历史变更记录请参见：

- `PROJECT_OVERVIEW.md` — 完整版本历史、验收记录和实现细节
- `TECH_DESIGN.md` — 技术架构和设计方案
- 项目根目录 `CHANGELOG.md` — 面向用户的版本变更摘要

## 3. 版本规划

版本按由易到难的顺序编排，严格按版本顺序开发。

### v1.0.8：格式与视图增强

#### 目标

扩展 Markdown 格式支持范围，优化分栏模式下的阅读连贯性；以编辑区为基准提升同步定位精度，并修复长文档与查找场景下的定位错位。

#### 开发范围

- LaTeX 公式渲染：支持行内公式（`$...$`）和块级公式（`$$...$$`）
- 编辑与预览同步滚动：以编辑区源码行为基准建立行号映射，滚动编辑区时预览区精确同步到对应内容；滚动预览区时按同一映射回到编辑区对应位置
- 修复长 Markdown 文档中编辑区与预览区定位错位：双向定位以编辑区源码行为基准，点击预览区跳转编辑区时准确定位到对应行
- 查找时分栏模式下编辑区跟随滚动并定位到匹配词

#### 验收标准

- 行内公式 `$E=mc^2$` 在预览中正确渲染为数学符号
- 块级公式 `$$\int_0^1 x\,dx$$` 在预览中居中显示并正确渲染
- 嵌套公式和特殊符号（如 `\frac{}{}`、`\sum`、矩阵等）正确显示
- LaTeX 渲染结果通过 DOMPurify 清理，不引入安全风险
- 同步定位以编辑区为基准：编辑区滚动时，预览区滚动到同一源码行对应的内容位置
- 滚动预览区时，编辑区按同一源码行映射回到对应位置
- 长文档中点击预览区定位编辑区、点击编辑区定位预览区，均以编辑区源码行为准，位置准确对应
- 分栏模式下查找或替换时，编辑区滚动并定位到当前匹配词
- 同步滚动不影响纯编辑模式和纯预览模式
- 文档内容变化后同步关系仍然正确
- 自动化测试、类型检查和生产构建通过

#### 本版本不做

- 不支持 LaTeX 编辑器工具栏或公式模板
- 不改变 Markdown 导出时的公式格式
- 不新增全文搜索或其他查找模式

### v1.0.9：编辑体验增强

#### 目标

提供常用的文本编辑辅助操作，减少手动添加符号和打开大纲的操作成本。

#### 开发范围

- 选中一段文字后按下引号、括号、大括号、中括号等符号时，自动用成对符号包裹选区
- `Ctrl+G` 快捷键唤出文档大纲

#### 验收标准

- 编辑区存在选区时按下 `"`、`'`、`(`、`)`、`[`、`]`、`{`、`}` 等符号，选区被对应符号成对包裹，原内容不被覆盖
- 无选区时按下这些符号保持原有输入行为
- 包裹操作支持撤销与恢复
- 在编辑区或预览区按 `Ctrl+G` 唤出大纲，行为与现有大纲入口一致，不与其他快捷键冲突
- 自动化测试、类型检查和生产构建通过

#### 本版本不做

- 不引入输入法级自动配对或智能补全
- 不改变大纲的标题提取规则、折叠交互与定位行为

---

### v1.0.10：文件类型扩展

#### 目标

支持打开 TXT 与 JSON 文件，预览区与编辑区显示相同内容，扩展轻量查看与编辑范围。

#### 开发范围

- 文件对话框、拖放、最近文件与 Windows“打开方式”支持 `.txt` / `.json` 文件
- 打开后编辑区与预览区显示相同内容（按纯文本展示，不进行 Markdown 渲染）

#### 验收标准

- 通过文件对话框、拖放、最近文件和 Windows“打开方式”可以打开 TXT 与 JSON 文件
- 打开后编辑区与预览区显示相同的纯文本内容
- 保存、另存为、会话恢复、未保存修改检查与关闭流程对 TXT/JSON 文件正常
- 不支持的扩展名仍显示明确提示
- 自动化测试、类型检查和生产构建通过

#### 本版本不做

- 不做 JSON 语法高亮、格式校验或折叠
- 不将 TXT 内容按 Markdown 渲染
- 不改变现有 Markdown 文件的行为

## 4. 暂不进入路线图

以下能力目前不安排版本：

- 登录与账号系统
- 云同步
- 团队协作
- AI 写作
- 在线插件市场
- 后端服务

这些方向只有在本地文件编辑体验稳定后，才重新评估。
