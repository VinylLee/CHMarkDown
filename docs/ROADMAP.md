# CHMarkDown 开发路线图

## 1. 文档目的

本文档用于记录 CHMarkDown 的版本目标和开发顺序。

执行规则：

- 严格按版本顺序开发
- 每次只实现一个版本
- 当前版本通过测试、构建和功能验收后，再进入下一个版本
- 路线图只定义目标和边界；开始某个版本前，再补充该版本的详细技术方案
- 不提前实现后续版本功能

## 2. 当前基线：v0.6.0

当前已经具备：

- 本地笔记的新建、编辑、保存和删除
- Markdown 编辑与实时预览
- 编辑区与预览区双向定位
- 编辑与预览模式切换时保持阅读位置、光标和选区
- 本地图片插入、粘贴、调整尺寸和导出
- 未保存修改提示
- 本地 JSON 数据保存
- Windows x64 便携版打包
- CHMarkDown 独立应用图标
- 当前应用图标使用 `resources/ChatGPT Image 2026年8月2日 20_24_25.png` 提供的设计
- 打开本地 `.md` / `.markdown` 文件
- 保存回原文件或另存为新文件
- 外部文件名与完整路径显示
- 本地笔记和外部文件统一显示在左侧文档列表
- 可关闭外部文件或经确认删除本地笔记
- portable 5 次启动中位时间由 3.689 秒降至 1.023 秒
- 同一 Release 提供快速便携 EXE 和轻量下载 ZIP
- 最近文件列表、单条移除和清除全部记录
- 拖放、命令行和 Windows“打开方式”打开 Markdown 文件
- 重启后恢复文档列表顺序、外部文件和当前选中项
- 当前文档查找、替换和 Markdown 标题大纲
- 基于编辑器光标位置的上下匹配导航及精简快捷键
- 选中 Markdown 原文后通过 `Ctrl+F` 直接查找选区内容
- 在编辑区或预览区选中文字后通过 `Ctrl+F` / `Ctrl+R` 立即查找
- 外部 Markdown 相对图片预览、插入、粘贴和另存为资源复制
- 本地笔记与外部文件统一导出 Markdown 或图片 ZIP
- 浅色、深色和跟随系统主题
- 编辑器字体、字号、默认打开模式和自动换行偏好
- 可配置的外部图片资源目录名称
- 编辑器偏好设置本地持久化与损坏回退

## 3. 版本规划

### v0.1.1：应用图标（已完成）

#### 目标

为 CHMarkDown 设置独立、清晰且适合 Windows 的应用图标，替换 Electron 默认图标。

#### 开发范围

- 设计或选定 CHMarkDown 图标
- 提供 Windows 打包使用的 `.ico` 文件
- 保留可继续编辑的源文件或高分辨率 PNG
- 在 Electron 窗口和 electron-builder 配置中使用新图标
- 检查便携版文件、任务栏和窗口标题栏中的图标显示

#### 验收标准

- 开发模式窗口显示 CHMarkDown 图标
- 打包后的 `.exe` 显示 CHMarkDown 图标
- 任务栏和窗口切换界面显示正确图标
- 图标在 16×16、32×32、48×48 和 256×256 等常见尺寸下清晰可辨
- `npm test`、`npm run build` 和便携版打包通过

#### 当前图标资源

- 用户提供的 1000×1000 RGBA PNG 保留为原始设计文件
- `resources/chmarkdown.png` 保存规范源图，`resources/chmarkdown.ico` 包含 16–256 像素的九档图标
- Electron 窗口、portable 主程序和后续托盘图标继续共用同一份 ICO
- 九档 ICO 解码、全部 161 项测试、生产构建、portable 和 ZIP 打包验证通过

#### 本版本不做

- 不调整编辑器功能
- 不重新设计整个应用界面

### v0.2.0：打开、保存和另存为 Markdown 文件（已完成）

#### 目标

让用户可以指定一个本地 Markdown 文件，在 CHMarkDown 中打开、编辑，并保存回原文件或另存为新文件。

#### 开发范围

- 通过“文件 > 打开”选择 `.md` 或 `.markdown` 文件
- 支持快捷键 `Ctrl+O`
- 打开后显示当前文件名和文件路径
- `Ctrl+S` 保存到当前文件
- “文件 > 另存为”以及 `Ctrl+Shift+S`
- 打开其他文件、关闭窗口或退出应用前检查未保存修改
- 文件读写继续通过 preload 和 IPC 完成
- 读写失败时显示用户可感知的错误提示
- 默认使用 UTF-8 读取和保存 Markdown

#### 验收标准

- 可以选择并打开本地 Markdown 文件
- 打开后内容和 Markdown 预览正确
- 保存会更新原文件
- 另存为会创建新文件，并将当前文档切换到新路径
- 取消文件对话框不会改变当前编辑内容
- 保存失败不会清除未保存状态
- 未保存内容不会在打开其他文件或退出时无提示丢失
- 渲染进程不能直接访问 Node.js 或本地文件系统
- `npm test` 和 `npm run build` 通过

#### 已采用的版本边界

- 外部 Markdown 文件与现有本地笔记库并存
- 相对图片路径解析和外部文件图片插入留到 v0.5.0
- 本版本不检测文件被其他程序修改的冲突，保存时直接写回当前路径

#### 本版本不做

- 不做云端文件同步
- 不自动修改用户 Markdown 的格式

### v0.2.1：启动速度与文档列表体验优化（已完成）

#### 目标

以缩短 Windows 便携版从启动到主窗口可用的时间为主要目标，同时修复 v0.2.0

- 建立冷启动、重复启动和主窗口可交互时间的基线

- 优化便携版压缩与解包配置，减少启动前等待
- 增加最高压缩级别的 Windows x64 ZIP 发行包，解压后直接运行
- 推迟非首屏必需模块和工作的加载
- 打开的外部 Markdown 文件加入左侧文档列表（已完成）
- 支持从左侧列表关闭外部文件（已完成）
- 支持从左侧列表删除本地笔记，并提供明确确认（已完成）
- 关闭当前文档时继续执行未保存修改保护（已完成）

#### 验收标准

- 在同一台测试设备上记录优化前后的冷启动和重复启动数据
- 便携版冷启动到主窗口可见的中位时间相比 v0.2.0 至少降低 50%
- 优化不关闭 `contextIsolation`，不降低文件与渲染安全配置
- 打开的外部文件立即出现在左侧列表，重复打开同一路径不会出现重复条目
- 关闭外部文件不会删除磁盘文件
- 删除本地笔记前显示确认，取消后笔记保持不变
- 关闭最后一个文档后编辑区回到正确空状态
- ZIP 发行包可完整解压并直接启动，不依赖系统浏览器内核
- `npm test`、类型检查、生产构建、便携版和 ZIP 打包通过

#### 实测结果

- v0.2.0 portable：3.666、3.648、3.689、3.846、3.860 秒
- v0.2.0 中位时间：3.689 秒
- v0.2.1 portable：2.843、1.023、1.093、1.021、0.872 秒
- v0.2.1 中位时间：1.023 秒

- 最终 portable 大小：241.2 MiB
- 最终 ZIP 大小：96.1 MiB，比快速便携 EXE 小 60.2%
- 最终仅保留 `zh-CN` 和 `en-US` Electron 语言资源
- 同一 v0.2.1 Release 同时提供快速便携 EXE 和轻量下载 ZIP

- 不实现最近文件持久化
- 不实现文件拖放或系统文件关联
- 不通过预加载全部数据来换取表面启动速度

### v0.2.2：编辑与预览模式滚动位置保持（已完成）

#### 目标

在分栏编辑模式和纯预览模式之间切换时，继续显示用户切换前正在阅读或编辑的
同一段内容，避免视图跳回文档顶部或其他无关位置。

#### 开发范围

- 切换模式前记录当前文档的可视位置
- 从分栏编辑切换到纯预览时，定位到编辑区当前可视内容对应的预览位置
- 从纯预览切换回分栏编辑时，恢复预览内容对应的编辑位置
- 优先使用现有 Markdown 源码行映射；无法精确映射时使用最近位置或滚动比例
- 在 DOM 完成模式切换后再恢复位置，避免被重新渲染覆盖
- 切换模式不改变光标、选区、未保存状态或图片选择状态

#### 已采用的实现

- 使用视口上方约三分之一处作为阅读锚点
- 优先通过现有 `data-source-line` 映射记录和恢复 Markdown 源码行
- 同时记录顶部、底部和滚动比例，在行映射不可用时安全回退
- 返回分栏模式后同时恢复编辑区和预览区位置
- 进入纯预览前保存 textarea 光标与选区，返回后恢复且不主动抢占焦点

#### 验收标准

- 在长文档中切换编辑和预览模式不会跳回顶部
- 标题、段落、列表和代码块附近均能保持在同一内容区域
- 连续多次切换模式时位置不会持续漂移
- 文档位于顶部或底部时切换后仍保持对应边界位置
- 不影响现有编辑区与预览区双向定位功能
- `npm test`、类型检查和生产构建通过

#### 验证结果

- 新增编辑区锚点、预览区锚点、顶部、底部和比例回退测试
- 全部 116 项自动化测试通过
- TypeScript 类型检查和生产构建通过

#### 本版本不做

- 不跨应用重启保存滚动位置
- 不在不同文档之间共享滚动位置

### v0.3.0：最近文件、拖放打开与系统文件关联（已完成）

#### 目标

降低重复打开 Markdown 文件的操作成本，让 CHMarkDown 更像一个完整的 Windows Markdown 编辑器。

#### 开发范围

- 最近打开文件列表
- 清除最近文件记录
- 将 `.md` 文件拖入窗口后打开
- 通过命令行参数接收文件路径
- 支持 Windows“打开方式”启动 CHMarkDown
- 最近文件不存在时给出提示，并允许从列表移除

#### 已采用的实现

- 最近文件记录保存在 Electron 用户数据目录的 `recent-files.json`
- 最多保留 12 条记录，忽略 Windows 路径大小写去重，最新打开的文件排在最前
- 文件成功进入编辑器后才更新最近记录，取消未保存修改提示时不改变记录
- 主进程只读取 preload/IPC 传入的本地路径，渲染进程不直接访问文件系统
- 应用使用单实例锁；第二次通过命令行或“打开方式”启动时复用并聚焦现有窗口
- 首次启动期间收到的文件路径会排队到渲染进程就绪后再处理
- 所有打开入口共用同一串行队列和未保存修改保护，避免多个请求互相覆盖
- portable 支持由用户在 Windows“打开方式”中选择；不主动写入系统注册表

#### 验收标准

- 最近文件按最后打开时间排列
- 点击最近文件可以直接打开
- 拖入 `.md` 文件可以打开
- 从资源管理器使用 CHMarkDown 打开 Markdown 文件时内容正确
- 无效路径或已删除文件不会导致应用崩溃
- 未保存修改保护在所有打开入口中保持一致

#### 验证结果

- 新增命令行参数解析、最近文件持久化、排序、去重、限量、移除和损坏记录测试
- 全部 130 项自动化测试通过
- TypeScript 类型检查、生产构建、portable 和 ZIP 打包通过

#### 本版本不做

- 不扫描磁盘寻找 Markdown 文件

### v0.3.1：上次会话文档恢复（已完成）

#### 目标

记录应用关闭时左侧文档列表中仍然打开的本地笔记和外部 Markdown 文件，并在
下次启动时恢复相同的文档集合和当前选中项。

#### 开发范围

- 记录文档列表中已打开条目的类型、ID 或文件路径
- 记录条目顺序和关闭应用时选中的文档
- 下次启动时恢复本地笔记条目
- 下次启动时重新读取外部 Markdown 文件，避免使用过期内容
- 用户主动从列表关闭的条目不在下次启动时恢复
- 外部文件已移动或删除时显示提示，并跳过无效条目
- 会话状态使用本地 JSON 保存，读写继续通过 preload 和 IPC 完成
- 只记录打开状态，不把未保存内容作为会话草稿静默保存

#### 验收标准

- 关闭应用前打开的文档在下次启动后重新出现在左侧列表
- 恢复后的文档数量、顺序和类型与关闭前一致
- 启动后优先选中上次关闭时正在查看的文档
- 用户关闭某个列表条目后，该条目不会在重启后再次自动出现
- 外部文件恢复时读取磁盘上的最新内容
- 单个无效文件不会阻止其他文档恢复或导致应用启动失败
- 会话文件损坏时回退到安全空状态并显示可感知提示
- `npm test`、类型检查、生产构建和便携版打包通过

#### 已采用的实现

- 会话状态保存在 Electron 用户数据目录的 `session.json`
- 本地笔记只记录 ID，外部文件只记录绝对路径，同时保存列表顺序和选中项
- 外部文件在启动时重新通过主进程读取磁盘内容，不缓存上次关闭时的正文
- 恢复失败的外部文件单独跳过并汇总提示，不影响其余文档
- 会话 JSON 严格校验；损坏时显示提示并以安全状态继续启动
- 文档列表变化和选中项变化后排队保存，窗口关闭前再次等待并保存最终状态
- 用户关闭外部文件或删除本地笔记后，对应条目立即从会话记录中移除

#### 验证结果

- 新增会话文件读写、格式校验、顺序、去重和损坏回退测试
- 新增会话恢复顺序、选中项、磁盘最新内容、失效文件隔离和已删除笔记测试
- 全部 139 项自动化测试通过
- TypeScript 类型检查、生产构建、portable 和 ZIP 打包通过
- 解压版启动恢复验证通过：失效文件被跳过、有效文件保留、上次选中项正确恢复

#### 本版本不做

- 不恢复未保存的编辑草稿
- 不在多台设备之间同步会话
- 不自动恢复已经被用户删除的本地笔记

### v0.4.0：文档搜索、替换与大纲（已完成）

#### 目标

提升长文档的编辑和导航效率。

#### 开发范围

- 当前文档查找
- 区分大小写和全词匹配
- 单个替换和全部替换
- 根据 Markdown 标题生成文档大纲
- 点击大纲跳转到对应标题
- 显示当前匹配数量和位置

#### 验收标准

- 查找和替换不会破坏 Markdown 内容
- 大文档中查找响应流畅
- 大纲层级与 Markdown 标题层级一致
- 编辑标题后大纲能够及时更新
- 大纲跳转与现有编辑/预览定位功能兼容

#### 已采用的实现

- 工具栏提供“查找”“替换”“大纲”入口，并支持 `Ctrl+F` 和 `Ctrl+H`
- 查找按字面文本匹配，支持区分大小写、Unicode 全词边界、上一个和下一个
- 面板实时显示当前匹配序号和总匹配数，Enter/Shift+Enter 可以继续导航
- 单个替换只修改当前匹配范围，全部替换从后向前修改，避免偏移量变化破坏原文
- 匹配定位会选中 Markdown 原文，并通过现有源码行映射同步滚动和高亮预览
- 大纲由 markdown-it token 生成，支持 h1–h6、ATX 和 Setext 标题并排除代码块内容
- 大纲直接依赖当前编辑草稿，标题变化后立即更新；点击后按当前模式定位编辑区或预览区

#### 验证结果

- 新增字面匹配、大小写、Unicode 全词边界、单个替换和全部替换测试
- 新增标题层级、源码行、Setext、行内 Markdown、代码块排除和实时更新测试
- 全部 148 项自动化测试通过
- TypeScript 类型检查、生产构建、portable 和 ZIP 打包通过
- 包内版本确认为 0.4.0，ZIP 结构完整并包含 `CHMarkDown.exe`

#### 本版本不做

- 不实现跨文件全文搜索
- 不建立搜索索引数据库

### v0.4.1：查找导航与快捷键优化（已完成）

#### 目标

让查找方向与编辑器当前光标位置保持一致，并减少不必要的组合键。

#### 开发范围

- 替换快捷键由 `Ctrl+H` 改为 `Ctrl+R`
- `Ctrl+F` 在查找关闭时打开、已打开时关闭
- 文档列表快捷键由 `Ctrl+Shift+B` 改为 `Ctrl+B`
- 下一个匹配从当前光标或选区末端向后查找
- 上一个匹配从当前光标或选区起点向前查找
- 到达文首或文末时继续循环查找
- 纯预览模式使用切换前保存的编辑器光标位置作为基准

#### 验收标准

- `Ctrl+H` 不再触发替换，`Ctrl+R` 可以打开替换面板
- 连续按两次 `Ctrl+F` 会打开再关闭查找面板
- `Ctrl+B` 可以折叠或展开文档列表，`Ctrl+Shift+B` 不再触发
- 光标位于多个相同词语之间时，上下查找选择正确方向的相邻匹配
- 当前匹配被选中后，继续查找以该匹配选区作为新基准
- 文档边界循环不会跳过第一个或最后一个匹配

#### 已采用的实现

- 提取统一的主修饰键快捷键匹配函数，明确排除 Shift 和 Alt 组合
- 查找导航直接读取 textarea 的 `selectionStart` 和 `selectionEnd`
- 下一个匹配使用选区末端，上一个匹配使用选区起点
- textarea 不存在时回退到模式切换前保存的选区，再回退到文首或文末
- 匹配索引计算保持为纯函数，并覆盖前向、后向和边界循环测试

#### 验证结果

- 新增光标前向、选区前向、光标后向、选区后向和边界循环测试
- 新增 `Ctrl+F`、`Ctrl+R`、`Ctrl+B` 及旧组合键排除测试

### v0.4.3：预览选区与快捷查找优化（已完成）

#### 目标

#### 开发范围

- 读取当前 Markdown 预览容器内的非空浏览器选区
- 预览区选中文字后按 `Ctrl+F`，填入查询并立即计算全部匹配
- 查找已打开时，如果存在新的编辑区或预览区选区，`Ctrl+F` 更新查询并保持面板开启

- 替换区域已打开且没有新选区时，再次按 `Ctrl+R` 关闭查找与替换面板

- 纯预览和分栏预览中的选中文字都能成为查询词
- 查找已打开时选中文字再按 `Ctrl+F`，查询和匹配数立即更新，面板不关闭
- 选中文字按 `Ctrl+R` 时查询同步更新且替换区域可见

#### 已采用的实现

- 通过浏览器 Selection 和 Range API 读取选区，并验证共同祖先节点位于当前预览容器内
- 预览选区优先于编辑器选区；编辑器选区仅在 textarea 当前聚焦时读取，避免复用失焦后的旧选区

- 快捷键解析同时读取查找和替换区域状态，使 `Ctrl+F` 与 `Ctrl+R` 分别切换对应界面
- 纯预览下先捕获选中文字，再复用现有模式切换与滚动位置恢复逻辑，最后处理查找动作
- 继续复用现有响应式原文匹配逻辑，不增加 DOM 文本搜索或文件系统权限

### v0.5.1：统一导出 Markdown 与图片资源（已完成）

#### 目标

重新在编辑器工具栏中提供统一的“导出”按钮，让本地笔记和外部 Markdown 文件

#### 开发范围

- 导出前检查未保存修改，并要求先保存最新内容

- 只要 Markdown 中包含图片引用，就导出为 `.zip` 压缩包
- 压缩包包含 Markdown 文件及所有可访问的本地图片资源

#### 验收标准

- 无图片文档导出后得到内容正确的 Markdown 文件
- 含图片文档导出后得到 ZIP，而不是单独的 Markdown 文件
- 解压后 Markdown 可以引用压缩包内附带的本地图片

- 渲染进程不直接访问本地文件系统
- `npm test`、类型检查、生产构建和便携版打包通过

#### 已采用的实现

- 工具栏导出按钮同时面向本地笔记与外部文件，继续复用现有保存前确认
- 主进程先分析图片引用并决定 `.md` 或 `.zip`，取消保存对话框不会创建文件
- 使用 markdown-it token 提取图片，忽略代码区域中的伪图片语法，并支持空格、括号和标题
- 本地笔记托管图片改写为 ZIP 内 `images/`；外部相对图片保持可用目录结构
- 远程图片 URL 原样保留，不下载；重复本地资源按规范绝对路径去重
- 缺失、越界、绝对路径或未知协议图片在创建导出文件前失败并显示提示
- 导出使用同目录临时文件，成功后再替换最终目标，避免压缩失败留下不完整文件
