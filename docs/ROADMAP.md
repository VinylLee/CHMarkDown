# CHMarkDown 开发路线图

## 1. 文档目的

本文档用于规划 CHMarkDown 后续版本的开发顺序。

执行规则：

- 严格按版本顺序开发
- 每次只实现一个版本
- 当前版本通过测试、构建和功能验收后，再进入下一个版本
- 路线图只定义目标和边界；开始某个版本前，再补充详细技术方案
- 不提前实现后续版本功能

## 2. 当前基线：v1.1.0

当前已完成的功能和历史变更记录请参见：

- `PROJECT_OVERVIEW.md` — 完整版本历史、验收记录和实现细节
- `TECH_DESIGN.md` — 技术架构和设计方案
- 项目根目录 `CHANGELOG.md` — 面向用户的版本变更摘要

## 3. 版本规划

版本按由易到难的顺序编排，严格按版本顺序开发。

### v1.0.10：文件类型扩展（已完成）

#### 目标

支持打开 TXT 与 JSON 文件，预览区与编辑区显示相同内容，扩展轻量查看与编辑范围。

#### 开发范围

- 文件对话框、拖放、最近文件与 Windows“打开方式”支持 `.txt` / `.json` 文件
- 打开后编辑区与预览区显示相同内容（按纯文本展示，不进行 Markdown 渲染）

#### 验收标准

- 通过文件对话框、拖放、最近文件和 Windows“打开方式”可以打开 TXT 与 JSON 文件
- 打开后编辑区与预览区显示相同的纯文本内容
- 保存、另存为、会话恢复、未保存修改检查与关闭流程对 TXT/JSON 文件正常
- 不支持的扩展名仍显示明确提示
- 自动化测试、类型检查和生产构建通过

#### 本版本不做

- 不做 JSON 语法高亮、格式校验或折叠
- 不将 TXT 内容按 Markdown 渲染
- 不改变现有 Markdown 文件的行为

---

### v1.1.0：优化响应速度（已完成）

#### 目标

优化大 Markdown 文档（数千行）下的输入与编辑响应速度，消除明显卡顿。

#### 开发范围

- 定位大文档输入、删除、撤销和滚动卡顿的热点（渲染管线、镜像测量、历史记录、字数统计、大纲与预览重渲染等）
- 对高频路径做节流、缓存或按需计算优化，降低每次输入的同步开销
- 保证长文档连续输入与双向滚动保持流畅

#### 已采用的实现

- 预览渲染、字数统计和大纲提取使用独立的短延迟合并任务；连续输入期间分别设置最长等待，避免每次按键同步执行全部全量计算
- 纯编辑模式不再重建隐藏的预览；切换到分栏或预览时先同步最新正文，保持显示结果正确
- 切换文档与打开大纲时立即同步派生内容，不让延迟任务造成旧内容闪现
- 编辑区复用换行起始位置索引，滚动镜像在一次定位中只校验一次布局，不再在二分查找每一步重复读取样式
- 预览区缓存源码行节点与行号索引，渲染结果变化后明确失效，连续滚动和定位不再重复扫描 DOM
- 新增 `measure:editor`，用固定的 2000 行 Markdown 和 24 次连续输入比较逐次全量计算与合并计算

#### 验收标准

- 数千行文档中输入、删除、撤销不出现明显卡顿
- 长文档中连续滚动编辑区与预览区保持流畅，同步不滞后
- 优化不减少已有功能、不降低 Electron 安全配置
- 性能改善使用同机、同脚本的多次测量数据验证，不以单次结果作结论
- 自动化测试、类型检查和生产构建通过

#### 验证结果

- 同机运行编辑性能脚本 7 次：逐次全量计算中位耗时 4094.7 ms，1.1.0 合并计算中位耗时 649.2 ms，改善 84.1%
- 42 个测试文件、415 项自动化测试通过
- TypeScript 类型检查和生产构建通过

#### 本版本不做

- 不重写渲染引擎或更换技术栈
- 不引入全文索引、虚拟列表等新功能
- 不改变 Markdown 渲染结果与编辑行为

## 4. 暂不进入路线图

以下能力目前不安排版本：

- 登录与账号系统
- 云同步
- 团队协作
- AI 写作
- 在线插件市场
- 后端服务

这些方向只有在本地文件编辑体验稳定后，才重新评估。
