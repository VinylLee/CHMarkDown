# CHMarkDown 开发路线图

## 1. 文档目的

本文档用于记录 CHMarkDown 的版本目标和开发顺序。

执行规则：

- 严格按版本顺序开发
- 每次只实现一个版本
- 当前版本通过测试、构建和功能验收后，再进入下一个版本
- 路线图只定义目标和边界；开始某个版本前，再补充该版本的详细技术方案
- 不提前实现后续版本功能

## 2. 当前基线：v0.2.0

当前已经具备：

- 本地笔记的新建、编辑、保存和删除
- Markdown 编辑与实时预览
- 编辑区与预览区双向定位
- 本地图片插入、粘贴、调整尺寸和导出
- 未保存修改提示
- 本地 JSON 数据保存
- Windows x64 便携版打包
- CHMarkDown 独立应用图标
- 打开本地 `.md` / `.markdown` 文件
- 保存回原文件或另存为新文件
- 外部文件名与完整路径显示

## 3. 版本规划

### v0.1.1：应用图标（已完成）

#### 目标

为 CHMarkDown 设置独立、清晰且适合 Windows 的应用图标，替换 Electron 默认图标。

#### 开发范围

- 设计或选定 CHMarkDown 图标
- 提供 Windows 打包使用的 `.ico` 文件
- 保留可继续编辑的源文件或高分辨率 PNG
- 在 Electron 窗口和 electron-builder 配置中使用新图标
- 检查便携版文件、任务栏和窗口标题栏中的图标显示

#### 验收标准

- 开发模式窗口显示 CHMarkDown 图标
- 打包后的 `.exe` 显示 CHMarkDown 图标
- 任务栏和窗口切换界面显示正确图标
- 图标在 16×16、32×32、48×48 和 256×256 等常见尺寸下清晰可辨
- `npm test`、`npm run build` 和便携版打包通过

#### 本版本不做

- 不调整编辑器功能
- 不重新设计整个应用界面

---

### v0.2.0：打开、保存和另存为 Markdown 文件（已完成）

#### 目标

让用户可以指定一个本地 Markdown 文件，在 CHMarkDown 中打开、编辑，并保存回原文件或另存为新文件。

#### 开发范围

- 通过“文件 > 打开”选择 `.md` 或 `.markdown` 文件
- 支持快捷键 `Ctrl+O`
- 打开后显示当前文件名和文件路径
- `Ctrl+S` 保存到当前文件
- “文件 > 另存为”以及 `Ctrl+Shift+S`
- 打开其他文件、关闭窗口或退出应用前检查未保存修改
- 文件读写继续通过 preload 和 IPC 完成
- 读写失败时显示用户可感知的错误提示
- 默认使用 UTF-8 读取和保存 Markdown

#### 验收标准

- 可以选择并打开本地 Markdown 文件
- 打开后内容和 Markdown 预览正确
- 保存会更新原文件
- 另存为会创建新文件，并将当前文档切换到新路径
- 取消文件对话框不会改变当前编辑内容
- 保存失败不会清除未保存状态
- 未保存内容不会在打开其他文件或退出时无提示丢失
- 渲染进程不能直接访问 Node.js 或本地文件系统
- `npm test` 和 `npm run build` 通过

#### 已采用的版本边界

- 外部 Markdown 文件与现有本地笔记库并存
- 相对图片路径解析和外部文件图片插入留到 v0.5.0
- 本版本不检测文件被其他程序修改的冲突，保存时直接写回当前路径

#### 本版本不做

- 不做云端文件同步
- 不自动修改用户 Markdown 的格式

---

### v0.3.0：最近文件、拖放打开与系统文件关联

#### 目标

降低重复打开 Markdown 文件的操作成本，让 CHMarkDown 更像一个完整的 Windows Markdown 编辑器。

#### 开发范围

- 最近打开文件列表
- 清除最近文件记录
- 将 `.md` 文件拖入窗口后打开
- 通过命令行参数接收文件路径
- 支持 Windows“打开方式”启动 CHMarkDown
- 最近文件不存在时给出提示，并允许从列表移除

#### 验收标准

- 最近文件按最后打开时间排列
- 点击最近文件可以直接打开
- 拖入 `.md` 文件可以打开
- 从资源管理器使用 CHMarkDown 打开 Markdown 文件时内容正确
- 无效路径或已删除文件不会导致应用崩溃
- 未保存修改保护在所有打开入口中保持一致

#### 本版本不做

- 不扫描磁盘寻找 Markdown 文件

---

### v0.4.0：文档搜索、替换与大纲

#### 目标

提升长文档的编辑和导航效率。

#### 开发范围

- 当前文档查找
- 区分大小写和全词匹配
- 单个替换和全部替换
- 根据 Markdown 标题生成文档大纲
- 点击大纲跳转到对应标题
- 显示当前匹配数量和位置

#### 验收标准

- 查找和替换不会破坏 Markdown 内容
- 大文档中查找响应流畅
- 大纲层级与 Markdown 标题层级一致
- 编辑标题后大纲能够及时更新
- 大纲跳转与现有编辑/预览定位功能兼容

#### 本版本不做

- 不实现跨文件全文搜索
- 不建立搜索索引数据库

---

### v0.5.0：外部 Markdown 图片与资源可移植性

#### 目标

让外部 Markdown 文件中的图片可以可靠预览，并让新插入的图片与文档一起移动。

#### 开发范围

- 解析相对于 Markdown 文件的图片路径
- 显示图片缺失提示
- 为外部文档插入图片时，将图片复制到可配置的资源目录
- 默认资源目录采用文档旁的 `images/`
- 保存时写入相对图片路径
- 另存为时明确处理关联图片

#### 验收标准

- 相对路径图片可以预览
- 原图移动到资源目录后，Markdown 引用仍然有效
- 文档和资源目录一起复制到其他位置后仍可使用
- 图片复制失败时不会写入无效引用
- 不允许通过图片路径读取约定范围外的任意敏感文件

#### 本版本不做

- 不上传图片到网络图床
- 不做云端资源管理

---

### v0.6.0：编辑器偏好设置

#### 目标

允许用户调整常用编辑体验，同时保持配置简单。

#### 开发范围

- 浅色、深色和跟随系统主题
- 编辑器字体和字号
- 默认打开模式：编辑、分栏或预览
- 自动换行开关
- 图片资源目录名称
- 设置保存在本机

#### 验收标准

- 设置修改后立即生效
- 重启应用后设置仍然保留
- 设置损坏或读取失败时回退到安全默认值
- 深色主题下编辑区、预览区和弹窗均清晰可读

#### 本版本不做

- 不提供插件系统
- 不提供在线主题市场

---

### v1.0.0：稳定版

#### 目标

在核心文件工作流稳定后发布第一个正式版本。

#### 开发范围

- 回归测试所有核心功能
- 补充文件读写、未保存保护和图片路径测试
- 检查大文件性能和内存占用
- 统一错误提示和空状态
- 检查键盘可访问性
- 完善 README、用户使用说明和发版说明
- 生成可分发的 Windows 便携版

#### 验收标准

- 打开、编辑、保存、另存为和恢复操作稳定
- 常见错误不会造成内容静默丢失
- Markdown 和图片在重启后保持可用
- 自动化测试、类型检查、构建和打包全部通过
- 没有阻塞发布的已知问题

## 4. 暂不进入路线图

以下能力目前不安排版本：

- 登录与账号系统
- 云同步
- 团队协作
- AI 写作
- 在线插件市场
- 后端服务

这些方向只有在本地文件编辑体验稳定后，才重新评估。
