## v1.0.1 — 可拖拽/隐藏侧边栏与笔记列表

### 目标

用户可以通过拖拽调整侧边栏菜单和笔记列表的宽度，也可以快速折叠/展开这些面板，从而获得更大的编辑空间。

### 现状分析

| 面板 | 当前宽度 | 定位方式 | 文件 |
|------|----------|----------|------|
| Sidebar（侧边栏菜单） | 210px 固定 | 硬编码 `width: 210px; min-width: 210px` | `src/components/Sidebar.vue` |
| NoteList（笔记列表） | 260px 固定 | 硬编码 `width: 260px; min-width: 260px` | `src/components/NoteList.vue` |
| NoteEditor（编辑器） | flex: 1 | 自动填充剩余空间 | `src/components/NoteEditor.vue` |

当前布局结构（在 `src/App.vue` 和 `src/views/NotesView.vue` 中）：

```
┌──────────┬──────────────┬──────────────────────────────┐
│ Sidebar  │ NoteList     │ NoteEditor                   │
│ 210px    │ 260px        │ flex: 1                      │
│ 固定     │ 固定         │ 自适应                        │
└──────────┴──────────────┴──────────────────────────────┘
```

### 功能需求

#### F1.1 — 可拖拽调整面板宽度

- **Sidebar**：右侧边缘出现拖拽手柄，hover 时显示，拖拽可调整宽度
  - 最小宽度：`160px`
  - 最大宽度：`360px`
  - 默认宽度：`210px`（保持现有默认值）
- **NoteList**：右侧边缘出现拖拽手柄，hover 时显示，拖拽可调整宽度
  - 最小宽度：`180px`
  - 最大宽度：`420px`
  - 默认宽度：`260px`（保持现有默认值）

拖拽交互规格：
- 光标悬停在拖拽手柄上时显示 `col-resize` 光标
- 拖拽时手柄高亮（颜色变为 `--color-primary`）
- 拖拽过程中显示实时宽度
- 释放鼠标时宽度生效，并保持到 `localStorage`

#### F1.2 — 折叠/展开面板

- **Sidebar 折叠**：Sidebar 顶部或底部添加折叠按钮
  - 折叠后 Sidebar 收起至 `0px`（完全隐藏），内容区扩展
  - 展开按钮出现在应用左侧边缘（悬浮式条状按钮）
  - 键盘快捷键：`Ctrl + B`（类似 VS Code 侧边栏切换）
- **NoteList 折叠**：NoteList 顶部 header 右侧添加折叠按钮
  - 折叠后 NoteList 收起至 `0px`，编辑器占满全部空间
  - 展开按钮出现在笔记视图左侧边缘
  - 键盘快捷键：`Ctrl + Shift + B`

折叠/展开动画：
- Sidebar：`transition: width 0.2s ease`
- NoteList：`transition: width 0.2s ease`
- 折叠时内部文字淡出（`opacity 0 → 0`），避免文字挤压变形

#### F1.3 — 状态持久化

- 面板宽度和折叠状态保存到 `localStorage`
- 键名约定：
  - `flowdesk:sidebar:width` — Sidebar 宽度
  - `flowdesk:sidebar:collapsed` — Sidebar 是否折叠
  - `flowdesk:notelist:width` — NoteList 宽度
  - `flowdesk:notelist:collapsed` — NoteList 是否折叠
- 应用启动时读取保存的状态

#### F1.4 — 全局快捷键

| 快捷键 | 功能 |
|--------|------|
| `Ctrl + B` | 切换 Sidebar 折叠/展开 |
| `Ctrl + Shift + B` | 切换 NoteList 折叠/展开 |

快捷键注册在 `App.vue` 级别（全局），以便在任意视图下都能触发。

#### `useResizable` Composable 设计

```typescript
// src/composables/useResizable.ts

interface UseResizableOptions {
  minWidth: number      // 最小宽度 (px)
  maxWidth: number      // 最大宽度 (px)
  defaultWidth: number  // 默认宽度 (px)
  storageKey?: string   // localStorage 键名，用于持久化宽度
  direction: 'left' | 'right'  // 拖拽手柄在哪一侧（拖拽方向相反）
}

interface UseResizableReturn {
  width: Ref<number>              // 当前宽度
  isResizing: Ref<boolean>        // 是否正在拖拽中
  handleRef: Ref<HTMLElement | null>  // 绑定到 ResizeHandle 的模板引用
  onMouseDown: (e: MouseEvent) => void  // mousedown 事件处理
  resetWidth: () => void           // 恢复默认宽度
}
```

核心逻辑：
1. `mousedown` 在手柄上时，记录起始位置和宽度，在 `document` 上注册 `mousemove` 和 `mouseup` 监听
2. `mousemove` 时计算偏移量，更新宽度（限制在 min/max 之间）
3. `mouseup` 时移除监听，将最终宽度写入 `localStorage`
4. 初始化时从 `localStorage` 读取已保存的宽度，无保存值时使用 `defaultWidth`

## v1.0.2 — 编辑区与预览区双向定位

### 目标

在笔记的分栏编辑模式下，用户点击预览区的某个位置后，编辑区能自动滚动到对应的 Markdown 源码位置；反之，在编辑区点击某行，预览区也能定位到对应的渲染结果位置。

### 现状分析

当前 NoteEditor 的分栏模式（`isEditing = true`）结构：

```
┌──────────────────────┬──────────────────────┐
│ editor-pane--edit    │ editor-pane--preview │
│ (textarea)           │ (v-html rendered)    │
│                      │                      │
│ Markdown 源码        │ HTML 渲染结果         │
│ 无行号               │ 无锚点标记            │
└──────────────────────┴──────────────────────┘
```

关键文件：`src/components/NoteEditor.vue`
- 编辑区：`<textarea>` 绑定 `editContent`
- 预览区：`<div class="content-preview" v-html="renderedMarkdown">`
- 渲染引擎：`markdown-it` 14.x

### 功能需求

#### F2.1 — 预览区点击 → 编辑区定位（Preview to Edit）

用户在预览区点击某段文字后，编辑区自动滚动到对应的 Markdown 源码位置。

**实现策略：**

markdown-it 渲染时，在每个块级元素上注入 `data-source-line` 属性，记录该元素对应的 Markdown 源码行号。然后在 textarea 中根据行号计算滚动位置。

具体步骤：
1. **Markdown 渲染注入源行号**
   - 利用 `markdown-it` 的 `renderer.render` 或自定义插件，为每个块级 token（heading、paragraph、list、blockquote、code block、table 等）生成的 HTML 元素添加 `data-source-line="<开始行号>"` 属性
   - 或者使用 `markdown-it-source-map` / `markdown-it-attrs` 等能力

   ```javascript
   // 自定义 markdown-it 插件
   md.renderer.rules.paragraph_open = (tokens, idx) => {
     const line = tokens[idx].map ? tokens[idx].map[0] + 1 : 0
     return `<p data-source-line="${line}">`
   }
   ```

2. **预览区点击事件处理**
   - 在 `handlePreviewClick` 中，检测当前点击目标元素
   - 向上遍历 DOM 树，查找最近的带 `data-source-line` 属性的元素
   - 提取源行号
   - 计算 textarea 中对应行的滚动偏移量

3. **编辑区滚动定位**
   - 计算 textarea 中对应行的 Y 位置：`lineHeight * (lineNumber - 1)`
   - 使用 `textarea.scrollTop = calculatedOffset` 滚动到对应位置
   - 可选：高亮对应行（通过 CSS overlay）

#### F2.2 — 编辑区光标 → 预览区定位（Edit to Preview）

用户在编辑区中移动光标或滚动时，预览区自动滚动到对应的渲染位置。

**实现策略：**

1. **从光标位置计算行号**
   - 监听 textarea 的 `click` 和 `keyup` 事件
   - 通过 `textarea.selectionStart` 和光标前的换行符数量计算当前行号

   ```typescript
   function getCurrentLineNumber(textarea: HTMLTextAreaElement): number {
     const textBeforeCursor = textarea.value.substring(0, textarea.selectionStart)
     return textBeforeCursor.split('\n').length  // 1-indexed
   }
   ```

2. **从行号找到预览区对应元素**
   - 在预览 DOM 中搜索 `[data-source-line="<行号>"]` 或最近的匹配元素
   - 优先精确匹配，无精确匹配时找最接近且 ≤ 当前行号的元素

3. **预览区滚动定位**
   - 使用 `element.scrollIntoView({ behavior: 'smooth', block: 'center' })`
   - 可选：高亮对应预览区域（短暂背景色变化动画）

#### F2.3 — 同步滚动（可选增强）

在滚动预览区或编辑区时，另一侧自动跟随滚动。这是一个自然的扩展。

**实现策略：**
- 编辑区 `scroll` 事件 → 计算当前可见的第一行 → 预览区定位
- 预览区 `scroll` 事件 → 计算当前可见的第一个块元素 → 获取 `data-source-line` → 编辑区定位
- 使用防抖（debounce 150ms）避免频繁触发

#### F2.4 — 用户界面提示

- 在预览区被点击触发定位时，编辑区对应行短暂高亮（约 1.5s 淡出）
- 在编辑区光标移动触发定位时，预览区对应块短暂高亮
- 工具栏添加一个切换按钮：开启/关闭双向定位（默认开启）
  - 图标：链接/同步样式
  - 复选框 toggle（类似 VS Code 的 markdown 预览同步滚动开关）

#### `markdownSourceMap` 工具设计

```typescript
// src/utils/markdownSourceMap.ts

/**
 * 为 markdown-it 实例注册 source-line 注入插件。
 * 渲染后每个块级 HTML 元素都会携带 data-source-line 属性。
 */
export function useSourceMapPlugin(md: MarkdownIt): void

/**
 * 在 DOM 元素树中向上查找最近的 data-source-line 属性值。
 * @returns 行号（1-indexed），未找到返回 null
 */
export function findSourceLine(element: HTMLElement): number | null

/**
 * 在预览 DOM 中查找与目标行号最匹配的元素。
 * 优先精确匹配，其次找 ≤ targetLine 的最大行号元素。
 */
export function findElementByLine(
  container: HTMLElement,
  targetLine: number
): HTMLElement | null
```

markdown-it 插件需要覆盖的 renderer rules（核心块级元素）：

| Token type | HTML 元素 | 说明 |
|------------|-----------|------|
| `heading_open` | `h1`–`h6` | 标题 |
| `paragraph_open` | `p` | 段落 |
| `bullet_list_open` | `ul` | 无序列表 |
| `ordered_list_open` | `ol` | 有序列表 |
| `blockquote_open` | `blockquote` | 引用 |
| `code_block` | `pre > code` | 代码块 |
| `fence` | `pre > code` | 围栏代码块 |
| `table_open` | `table` | 表格 |
| `hr` | `hr` | 分割线 |

## 技术风险评估

| 风险 | 影响 | 缓解措施 |
