# FlowDesk 应用内确认弹窗与未保存修改处理设计

## 背景

FlowDesk 当前在渲染进程中使用 `window.confirm()` 处理未保存笔记、笔记删除、待办删除和导出前保存确认。在 Windows 的 Electron 环境中，关闭这类原生 JavaScript 对话框后，WebContents 可能无法恢复焦点，表现为编辑光标消失、输入控件不可编辑或界面点击无响应。

此外，现有流程还存在以下相关问题：

- 通过侧栏离开笔记页面时不会检查未保存修改。
- 编辑器在异步写盘真正成功前就清除 dirty 状态。
- 保存失败不会阻止后续切换或离开。
- 导出使用固定 100ms 等待保存，可能导出旧数据。

## 目标

- 移除应用业务代码中的所有 `window.confirm()`。
- 使用 Vue 应用内异步弹窗统一承载确认交互。
- 离开未保存笔记时提供“保存并离开”“放弃修改”“取消”三个操作。
- 仅在写盘成功后清除 dirty 状态并继续原操作。
- 保存失败时留在当前编辑状态并显示用户可感知的提示。
- 笔记删除、待办删除和导出前保存复用同一套确认能力。
- 为关键决策流程增加可重复执行的自动化回归测试。

## 非目标

- 不修改本地 JSON 数据结构。
- 不新增后端、登录、同步或自动保存功能。
- 不重构整个笔记状态管理体系。
- 不依赖升级 Electron 来规避当前问题。
- 不改变现有页面整体布局和视觉风格。

## 方案选择

采用 Vue 应用内异步确认弹窗，而不是 Electron 原生消息框或关闭对话框后强制恢复焦点。

原因：

- 完全绕开导致问题的原生 JavaScript 对话框焦点链路。
- 可以支持三个明确操作，而不受 `window.confirm()` 二选一限制。
- 笔记和待办可以复用一致的交互与样式。
- 不需要新增运行时依赖或扩大 Electron IPC 接口。

## 组件与职责

### `useConfirm`

维护全局确认请求的响应式状态，并提供 Promise 风格接口。调用方提交标题、说明、按钮文字和危险操作样式，等待用户选择后得到明确结果。

结果类型保持有限且明确：

- `confirm`：主操作，例如保存并离开或确认删除。
- `secondary`：可选的次操作，例如放弃修改。
- `cancel`：取消当前操作。

同一时间只显示一个确认请求。弹窗关闭后必须清理请求状态，避免透明遮罩残留并拦截点击。

### `ConfirmDialog`

由 `App.vue` 挂载一次，负责：

- 显示标题、说明和二至三个操作按钮。
- 将点击结果返回给 `useConfirm`。
- 使用固定遮罩阻止弹窗期间操作背景内容。
- 支持按 Escape 取消。
- 弹窗出现时聚焦安全的取消按钮，关闭后不依赖原生窗口焦点恢复。

### 未保存修改决策

将未保存修改的决策流程抽成独立的异步函数，输入 dirty 状态、弹窗选择函数和保存函数，输出是否允许继续：

- 未修改：直接允许继续。
- 保存并离开：等待保存；成功才允许继续，失败则阻止。
- 放弃修改：允许继续。
- 取消：阻止继续。

该函数不依赖 Vue 组件 DOM，便于直接测试全部分支。

### `NoteEditor`

- 保存函数改为异步并返回成功与否。
- 保存进行中阻止重复提交。
- 只有父级持久化成功后才清除 dirty 状态。
- 对外暴露 `isDirty` 和异步 `save()`，供切换笔记、路由离开及导出流程复用。
- 导出前若有修改，先通过应用内弹窗确认并等待真实保存结果，不再使用固定延时。

### `NotesView`

- 笔记切换和新建前统一调用未保存修改决策。
- 使用 Vue Router 的离开守卫覆盖侧栏导航。
- 保存处理返回布尔结果；成功更新列表并提示，失败提示错误并返回 `false`。
- 选择当前笔记时不重复弹出未保存确认。

### 删除确认

笔记删除与待办删除改用 `useConfirm`。确认结果为 `confirm` 时才执行删除，取消时不改变数据。

## 数据流

```text
用户发起切换/新建/离开
  -> 检查编辑器 isDirty
  -> 未修改：继续
  -> 已修改：显示应用内确认弹窗
       -> 保存并离开：await editor.save()
            -> 成功：清除 dirty，继续
            -> 失败：保留 dirty，显示错误，停止
       -> 放弃修改：继续
       -> 取消：停止
```

## 错误处理

- IPC 保存失败必须由 `NotesView` 捕获并显示错误 toast。
- 保存失败时 `NoteEditor.isDirty` 保持为 `true`。
- 保存失败不得继续切换笔记、创建笔记、离开路由或导出。
- 弹窗 Promise 必须在确认、次操作和取消三条路径上都得到解决。
- 组件卸载或请求被替换时按取消处理，避免悬空 Promise。

## 测试策略

新增开发依赖 `vitest`，与现有 Vite/TypeScript 技术栈配合，不增加运行时依赖。

自动化测试至少覆盖：

- 未修改时不弹窗并允许继续。
- 保存并离开且保存成功时允许继续。
- 保存并离开但保存失败时阻止继续。
- 放弃修改时不保存并允许继续。
- 取消时不保存并阻止继续。
- 确认控制器在三个结果后均清理活动状态。

静态与构建验证：

- 搜索业务源码，确认不存在 `window.confirm()`。
- 运行全部 Vitest 测试。
- 运行 TypeScript 类型检查。
- 运行完整生产构建。

手动回归路径：

- 编辑笔记后切换另一篇笔记，分别验证三个操作。
- 编辑笔记后通过侧栏进入待办页面，分别验证三个操作。
- 模拟保存失败，确认仍停留在当前笔记且 dirty 状态保留。
- 删除笔记和待办时验证应用内确认弹窗。
- 导出未保存笔记时验证先保存、保存失败停止导出。

## 成功标准

- 所有原生 `window.confirm()` 已移除。
- 未保存修改的三个操作行为与设计一致。
- 保存失败不会丢失编辑状态或允许离开。
- 关闭应用内弹窗后编辑器可继续点击和输入。
- 现有待办、笔记、图片和导出功能不受影响。
- 自动化测试、类型检查和生产构建全部通过。
